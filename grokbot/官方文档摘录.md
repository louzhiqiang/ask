# Grok Bot 官方资料研究笔记

研究日期：2026-11-08（Asia/Shanghai，中国标准时间）。本稿为官方文档研究，不含小红书用户实测。

## 1. 云电脑／box 与浏览器执行
- **背景**：工作需要跨网站、文件和工具落地，而不只是生成一段聊天答案。[发布介绍](https://x.ai/news/introducing-grok-bot)
- **原理**：同一账户的 Bots 共用持久云电脑、文件系统、终端、浏览器会话与登录；每个 Bot 有独立屏幕，可并行操作，每屏同一时刻运行一个电脑操作任务。不同用户的电脑隔离。[总览](https://cursor.com/docs/grok-bot)；[指南](https://cursor.com/docs/grok-bot/work)
- **官方推荐用法**：有连接器优先连接器，没有则用浏览器；在 `/workspace` 按项目保存长期文件；可打开电脑观察，需要时接管。关电脑或关闭客户端不终止云端任务。[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：减少人在多个工具间搬运；不是“所有网站都能操作”，网站可能反自动化、会话过期、需要验证码／人工验证。Bot 间的独立屏幕不是安全隔离。更新电脑可能移除安装的软件，恢复／重置可能丢最近未保存数据。[总览](https://cursor.com/docs/grok-bot)；[指南](https://cursor.com/docs/grok-bot/work)

## 2. 连接器、插件与自定义 MCP
- **背景**：跨 Gmail、Drive、Slack 等服务读写，避免脆弱的网页点击。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)
- **原理**：连接器提供结构化工具；OAuth token 保存在连接器后端，不交给 Bot、不放在云电脑。连接应用通常全账户可用。没有目录应用时可连接自定义 MCP；只有 API 时官方提供 tinkabot 封装、测试 MCP 与技能，发布须用户同意。[指南](https://cursor.com/docs/grok-bot/work)；[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)
- **官方推荐用法**：先连接经常用的应用；首个任务明确来源、权限和输出，缺失来源时报告失败，不用陈旧资料替代。[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：结构化调用更可靠，但权限、服务限流和过期登录仍会阻塞；管理员禁用连接器不等于禁用对应网站，后者还需网络策略。[指南](https://cursor.com/docs/grok-bot/work)

## 3. Memory：长期岗位与个人偏好
- **背景**：重复任务不应每次重新交代角色与习惯。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)
- **原理**：Bot 保留偏好、规则、工作摘要及日期日志；每个 Bot 的记忆独立，姓名／时区等少量个人信息跨 Bot 共享。可要求记住、更正、忘记。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)
- **官方推荐用法**：长期规则写入记忆，一次性细节放任务消息；为有独立来源、规则或周期的工作单建 Bot。主 Bot 负责协调。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)
- **效果与限制**：减少重复解释，但记忆会过时；价格、预算等动态数字必须查当前来源；安全边界不应只靠记忆，应配合审批；密码与卡不进记忆。[指南](https://cursor.com/docs/grok-bot/work)

## 4. Skills 与示范教学
- **背景**：把一次成功方法沉淀，避免重复提示。[技能文档](https://docs.x.ai/grok-bot/skills-routines-and-automations)
- **原理**：技能是可复用指令，包含步骤、决策规则、输入、验证、输出与审批边界；可跨 Bots 使用但仍需权限。Teach a task 记录最多十分钟可见电脑操作，不录麦克风，生成草稿技能。[指南](https://cursor.com/docs/grok-bot/work)
- **官方推荐用法**：先完成一次真实任务，再保存技能；补充失败处理与批准条件，用安全输入测试后才自动化。直接按名称调用技能。[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：方法复用而非训练新模型；教学逐步开放，草稿不是自动可靠；示范中不要暴露秘密。桌面 `/` 技能菜单已移除，不应照旧教程操作。[指南](https://cursor.com/docs/grok-bot/work)；[10月7日更新](https://x.ai/changelog/bot)

## 5. Routines：定时与事件自动化
- **背景**：日报、风险巡检、收件响应需要无人值守执行。[技能文档](https://docs.x.ai/grok-bot/skills-routines-and-automations)
- **原理**：Routine 给一个拥有者 Bot 指定何时运行：时间表，或 Slack、GitHub、Linear、Sentry、PagerDuty、邮件及 webhook 等支持事件。运行在云端；只处理触发器建立后的新事件。账号级事件集成与普通应用连接可能分开配置。[技能文档](https://docs.x.ai/grok-bot/skills-routines-and-automations)
- **官方推荐用法**：明确拥有者、时区、输入源、交付地点、审批点、缺源处理；触发条件窄；先测试，检查取数、证据和失败状态；先自动准备再自动执行。[技能文档](https://docs.x.ai/grok-bot/skills-routines-and-automations)；[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：人离线仍可运行；测试是真实动作，不是沙盒；广泛监听会增加噪声与用量。删除停止未来运行且不可撤销；长期离开可能暂停。10月23日日志称总计每小时最多300次、每 routine 200次，不能理解为无限并发或 SLA。[指南](https://cursor.com/docs/grok-bot/work)；[更新日志](https://x.ai/changelog/bot)

## 6. 多 Bot、群聊与临时子代理
- **背景**：研究、写作、审校分工，避免用户作为人工路由器。[发布介绍](https://x.ai/news/introducing-grok-bot)
- **原理**：长期 Bot 可互相异步交接；群聊可选2—6个 Bots，普通发言让 Bots 决定响应，@ 指定对象。共享 `/workspace` 文件支持接力。官方日志确认存在后台 subagents，Stop 会结束其工作与待审批卡，但所读公开文档没有完整公开子代理调度机制。[指南](https://cursor.com/docs/grok-bot/work)；[10月14日更新](https://x.ai/changelog/bot)
- **官方推荐用法**：每阶段一个负责人，例如研究员收集引用→写作者成稿→审校员核查；长期岗位与临时助手不要混淆。[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：并行减少人为传话；Bot 发往群的交接为纯文本，图片需直接发给需要检查的 Bot；过多并行交接会重复劳动、制造噪声。[指南](https://cursor.com/docs/grok-bot/work)

## 7. Cloud Agents 与 Projects：编码委派
- **背景**：把复现、修复、代码交付交给专门执行环境。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)
- **原理**：Bot 可把编码任务交给运行于另外电脑的 Cursor Cloud Agent；遵循既有 Cloud Agent 控制，管理员可禁用。完成后 Bot 把最终报告引用的文件复制回来并附在回复中。Project 是会计划并运行自身 agents 的 Cloud Agent。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)；[文件文档](https://docs.x.ai/grok-bot/files-and-results)；[9月18日更新](https://x.ai/changelog/bot)
- **官方推荐用法**：从复现材料与明确修复目标交接，检查返回文件、日志和 PR，而非只接受口头完成。[发布介绍](https://x.ai/news/introducing-grok-bot)；[文件文档](https://docs.x.ai/grok-bot/files-and-results)
- **效果与限制**：编码环境与共享 box 不同；启动权限由团队政策控制；不能把生成 PR 等同于已审查或可直接合并。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)

## 8. Pages／Canvas 与可检查文件
- **背景**：结果需持续更新、可阅读和共享，而不是散落聊天。[文件文档](https://docs.x.ai/grok-bot/files-and-results)
- **原理**：Page 是 Bot 生成的报告、备忘、仪表盘、tracker，可含表格、图表、筛选与开关；存于 Library，也可由 routine 更新。Canvas 与 document 在界面统一称 Page。[文件文档](https://docs.x.ai/grok-bot/files-and-results)；[10月11日更新](https://x.ai/changelog/bot)
- **官方推荐用法**：指定用途、字段和验收标准；让 Bot 修改同一页；关键结论附来源、时间戳与未解决问题。[文件文档](https://docs.x.ai/grok-bot/files-and-results)
- **效果与限制**：页面控件只改变当前显示，不保存底层内容；只有 Bot 修改页面。新页默认私有，公开链接可免登录阅读，不放敏感信息。开放与分享选项受版本和团队政策影响。[文件文档](https://docs.x.ai/grok-bot/files-and-results)

## 9. Channels：Slack、X 与邮件
- **背景**：用户在现有工作流里交任务，无需只在独立 app 中操作。[产品总览](https://docs.x.ai/grok-bot)
- **原理**：共享 Bot 可在 Slack 回线程、读已加入频道、响应提及；个人私聊与共享频道使用的身份／电脑不同。Bots 可拥有独立邮箱；公开 X 搜索和帖子读取不必连接 X 账号。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)；[9月26日与10月11日更新](https://x.ai/changelog/bot)
- **官方推荐用法**：以具体请求触发，交付草稿等待审阅；在来源系统保留证据链接。Slack 集成、事件 routine、普通 Slack 连接器不是一回事。[产品总览](https://docs.x.ai/grok-bot)；[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：未关联账号的 Slack 用户功能受限，不能借用拥有者私有登录；共享场景要检查谁能读回复。读 X 与代用户发帖／发消息的授权不是同一件事。[10月26—27日更新](https://x.ai/changelog/bot)

## 10. Vault、Secure Forms、审批与安全
- **背景**：需要真实执行但不能让密码、支付值进入普通聊天与模型上下文。[Vault](https://docs.x.ai/grok-bot/vault)
- **原理**：登录顺序为 Vault→连接的密码管理器→Secure Form；秘密直接填入网页，Bot 不见密码、卡号、安全码；Bot 可以看到联系信息和有哪些登录。API key 用安全秘密卡。Auto Review 检查工具和电脑动作，自定义 Ask first 可设置强审批点。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)；[安全](https://docs.x.ai/grok-bot/security)
- **官方推荐用法**：不把秘密发普通聊天；发信、发布、删除等不可逆动作配置 Ask first；SSO、passkey、二维码、验证等无法自动完成时人工接管。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)；[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：Auto Review 降低提示注入风险但不能消除；同账户 Bots 共享电脑和 Vault，不是逐 Bot 安全边界。支付及共享 Bot Vault 文档存在新旧差异，见开头，不能承诺永久免审批付款。[工作方式](https://docs.x.ai/grok-bot/how-grok-bot-works)；[更新日志](https://x.ai/changelog/bot)

## 11. 语音、移动端与通知
- **背景**：人在外面也能交办和审阅任务。[产品总览](https://docs.x.ai/grok-bot)
- **原理**：聊天之外可语音通话、发语音笔记；桌面与手机可接续上下文。语音备忘录支持逐词高亮与点词跳转；挂断时未完成工作可以继续并在聊天交付。[发布介绍](https://x.ai/news/introducing-grok-bot)；[9月18—22日更新](https://x.ai/changelog/bot)
- **官方推荐用法**：用语音交代任务，但仍把完成标准和审批点说清；重要结果回聊天留档、检查证据。[指南](https://cursor.com/docs/grok-bot/work)
- **效果与限制**：语音不是免审批通道；连接、麦克风与账户能力影响体验，不能把语音调用等同于会议机器人入会能力。[10月22日更新](https://x.ai/changelog/bot)；[指南](https://cursor.com/docs/grok-bot/work)

## 12. Team Bots、模板与企业治理
- **背景**：把专家方法沉淀为整个团队可用的岗位，而不复制每个人的手工流程。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)
- **原理**：模板分享给别人复制配置，不共享原电脑、登录和历史；Team Bot 则是多个成员访问同一岗位，每人对话私有，DM 通常用该成员电脑／连接器／用量；群场景使用共享 Bot 自己的电脑，管理员提供的技能、文件和秘密可用于成员聊天。[指南](https://cursor.com/docs/grok-bot/work)；[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)
- **官方推荐用法**：为团队岗位整理技能、文件、权限和负责人，再授权共享；先小范围试用，保留审批和数据边界。[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)
- **效果与限制**：共享专家方法但不应把个人私密对话当成团队知识库；模板可能暴露配置中的内部 URL 或秘密，分享前清理。管理员可控制连接器、Cloud Agent、共享等；网络策略、动作记录等属于特定企业能力。[指南](https://cursor.com/docs/grok-bot/work)；[团队文档](https://docs.x.ai/grok-bot/teams-and-enterprises)

## 13. 官方玩法与效果的证据口径
- 跨源晨报：聚合邮件、日历、Slack、文档；把例行检查交给 routine。预期是减少切换工具，官方总览未提供对照实验或节省时长。[产品总览](https://docs.x.ai/grok-bot)
- 客户风险周报：读取使用量与支持信号、列带链接风险名单，不擅自接触客户。是官方示例，不是保证识别率。[指南](https://cursor.com/docs/grok-bot/work)
- 会议笔记→行动项→Slack 草稿：标责任人，发送前审批；官方示例不保证所有纪要可自动正确解析。[产品总览](https://docs.x.ai/grok-bot)
- 招聘／费用／bug 等岗位 Bot：同类工作长期归一 Bot，积累记忆、技能，再定时化；效果以交付可核查文件和实际系统状态衡量，而非仅看回答流畅度。[发布介绍](https://x.ai/news/introducing-grok-bot)；[指南](https://cursor.com/docs/grok-bot/work)
